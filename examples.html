Worked Examples

Each example below follows the same pattern: a problem statement, a step-by-step solution using the theory from the corresponding page, and a small self-contained JavaScript snippet at the end that reproduces the same numbers. The code is copy-pasteable - drop it into a browser console or a Node.js file and it will print the exact same results shown here, using the same math the Plotting page itself uses.

Example 1: Two-Body Propagation

Problem Statement

A spacecraft orbiting Earth ($\mu = 398600.4418\ \text{km}^3/\text{s}^2$) is observed at position $\vec{r}_0 = [7000, 0, 0]$ km with velocity $\vec{v}_0 = [0, 8, 0.6]$ km/s. Find its position and velocity one hour ($\Delta t = 3600$ s) later, using the exact universal-variable method described on the Two-Body page.

Solution

First, gather the basic quantities: $r_0 = |\vec{r}_0| = 7000$ km, $v_0 = |\vec{v}_0| = 8.0225$ km/s, and the initial radial velocity $v_{r0} = \frac{\vec{r}_0\cdot\vec{v}_0}{r_0} = 0$ (since $\vec{r}_0$ and $\vec{v}_0$ happen to be perpendicular here). From these, $\alpha = \frac{2}{r_0} - \frac{v_0^2}{\mu} = 0.00012425\ \text{km}^{-1}$, so $a = 1/\alpha = 8048.33$ km. Since $\alpha > 0$, this confirms the orbit is an ellipse (as expected, since the specific energy $\frac{v_0^2}{2}-\frac{\mu}{r_0} = -24.7629\ \text{km}^2/\text{s}^2$ works out negative, matching $-\mu/2a$).

With $\alpha$ known, the initial guess for the universal anomaly is $\chi_0 = \sqrt{\mu}\,\Delta t\,\alpha \approx 282.40$. Newton-Raphson iteration on the universal Kepler equation converges in three steps: 

iter 1: chi = 282.335925   correction = -6.458e-2
iter 2: chi = 282.335925   correction =  1.609e-8
iter 3: chi = 282.335925   correction = -2.100e-15   (converged)

From the converged $\chi = 282.335925$ and $z = \chi^2\alpha$, the Lagrange coefficients work out to $f = -1.299506$, $g = -5.497024$ s, $\dot f = 4.9157\times 10^{-6}\ \text{s}^{-1}$, and $\dot g = -0.769502$. As a check, $f\dot g - \dot f g = 1.0000000000$ - confirming the arithmetic is self-consistent. Applying these gives the final state:

$$ \begin{aligned} \vec{r}(3600\,\text{s}) &= [-9096.54,\ -43.98,\ -3.30]\ \text{km} \qquad (|\vec{r}| = 9096.65\ \text{km}) \\ \vec{v}(3600\,\text{s}) &= [0.03441,\ -6.15602,\ -0.46170]\ \text{km/s} \qquad (|\vec{v}| = 6.17340\ \text{km/s}) \end{aligned} $$

As a sanity check, specific energy and angular momentum both come back essentially unchanged from their initial values ($-24.76292026$ km²/s² and $56157.279$ km²/s respectively, matching to all displayed digits) - exactly what's expected from an exact closed-form propagation with no truncation error. For reference, this orbit's full period works out to $T = 7185.71$ s ($\approx 2.0$ hours), so this one-hour step covers about half the orbit.

Code

function stumpffC(z) {
  if (z > 1e-6) { const s = Math.sqrt(z); return (1 - Math.cos(s)) / z; }
  if (z < -1e-6) { const s = Math.sqrt(-z); return (Math.cosh(s) - 1) / (-z); }
  return 0.5 - z / 24 + z * z / 720;
}
function stumpffS(z) {
  if (z > 1e-6) { const s = Math.sqrt(z); return (s - Math.sin(s)) / (s ** 3); }
  if (z < -1e-6) { const s = Math.sqrt(-z); return (Math.sinh(s) - s) / (s ** 3); }
  return 1 / 6 - z / 120 + z * z / 5040;
}

// Exact two-body propagation via universal variables (Curtis, Alg. 3.4)
function keplerStep(r0v, v0v, dt, mu) {
  const r0 = Math.hypot(...r0v), v0 = Math.hypot(...v0v);
  const vr0 = (r0v[0]*v0v[0] + r0v[1]*v0v[1] + r0v[2]*v0v[2]) / r0;
  const sqrtMu = Math.sqrt(mu);
  const alpha = 2 / r0 - (v0 * v0) / mu;

  let chi = sqrtMu * dt * alpha; // ellipse initial guess
  let C = 0.5, S = 1/6, z = 0, r = r0, ratio = 1, iter = 0;
  while (Math.abs(ratio) > 1e-10 && iter < 100) {
    z = chi * chi * alpha;
    C = stumpffC(z); S = stumpffS(z);
    r = chi*chi*C + (vr0*r0/sqrtMu)*chi*(1 - z*S) + r0*(1 - z*C);
    const F = sqrtMu*dt - chi**3*S - (vr0*r0/sqrtMu)*chi**2*C - r0*chi*(1 - z*S);
    ratio = F / r; chi += ratio; iter++;
  }

  const f = 1 - (chi*chi/r0)*C;
  const g = dt - (chi**3/sqrtMu)*S;
  const rVec = r0v.map((x, i) => f*x + g*v0v[i]);
  const rNew = Math.hypot(...rVec);
  const fdot = (sqrtMu/(rNew*r0)) * (z*S - 1) * chi;
  const gdot = 1 - (chi*chi/rNew)*C;
  const vVec = r0v.map((x, i) => fdot*x + gdot*v0v[i]);

  return { r: rVec, v: vVec, iterations: iter, checkfgFdotG: f*gdot - fdot*g };
}

const mu = 398600.4418;
const result = keplerStep([7000, 0, 0], [0, 8, 0.6], 3600, mu);
console.log(result);
// r: [-9096.54, -43.98, -3.30], v: [0.0344, -6.1560, -0.4617], checkfgFdotG: 1.0000...

Example 2: CR3BP Halo Orbit

Problem Statement

Using the Earth-Moon mass ratio $\mu = 0.0121505856$, propagate the halo orbit initial condition $\vec{r}_0 = [1.0220215127,\ 0,\ -0.1820967615]$, $\vec{v}_0 = [0,\ -0.1032563411,\ 0]$ (nondimensional) forward to $t_f = 1.51111$, and confirm the Jacobi constant is conserved, using the adaptive integrator described on the CR3BP page.

Solution

First, evaluate the initial acceleration directly from the equations of motion. The distances to Earth and Moon are $r_1 = |[x+\mu, y, z]| = 1.05008150$ and $r_2 = |[x-1+\mu, y, z]| = 0.18527537$ (in units where the Earth-Moon distance is 1) - note how much closer this point is to the Moon, consistent with it orbiting the $L_2$ point beyond the Moon. Plugging into the CR3BP equations of motion gives the initial acceleration $\vec{a}_0 = [-0.13207299,\ 0,\ 0.50324808]$.

The Jacobi constant at this initial state works out to $C_0 = 3.0465004406$. Rather than hand-stepping through all seven stages of the Dormand-Prince method here (that's what the code below is for), the key result is what comes out the other end: the adaptive integrator accepted 465 steps to reach $t_f = 1.51111$, automatically sizing each one based on its own local error estimate. The final state comes out to

$$ \vec{r}(t_f) = [1.02202148,\ 0.00000008,\ -0.18209676], \qquad \vec{v}(t_f) = [0.00000009,\ -0.10325632,\ -0.00000042] $$

which is within $4.4\times 10^{-7}$ (nondimensional distance) of the starting state - confirming this is indeed a (near-)periodic orbit, closing back up on itself after one period. The Jacobi constant at $t_f$ comes out to $3.0465004406$ as well, a relative change of only $4.1\times 10^{-12}$ - essentially machine precision, despite this being a numerically-integrated chaotic three-body trajectory rather than a closed-form solution.

Code

function CR3B_ode(s, mu) {
  const [x, y, z, vx, vy, vz] = s;
  const r1v = [x + mu, y, z], r2v = [x - (1 - mu), y, z];
  const r1 = Math.hypot(...r1v), r2 = Math.hypot(...r2v);
  const ax = 2*vy + x - (1-mu)*r1v[0]/r1**3 - mu*r2v[0]/r2**3;
  const ay = -2*vx + y - (1-mu)*r1v[1]/r1**3 - mu*r2v[1]/r2**3;
  const az = -(1-mu)*r1v[2]/r1**3 - mu*r2v[2]/r2**3;
  return [vx, vy, vz, ax, ay, az];
}
function jacobiConstant(s, mu) {
  const [x, y, z, vx, vy, vz] = s;
  const r1 = Math.hypot(x + mu, y, z), r2 = Math.hypot(x - (1 - mu), y, z);
  return x*x + y*y + 2*(1-mu)/r1 + 2*mu/r2 - (vx*vx + vy*vy + vz*vz);
}

// Dormand-Prince RK45 coefficients (Butcher tableau)
const A = [[],[1/5],[3/40,9/40],[44/45,-56/15,32/9],
  [19372/6561,-25360/2187,64448/6561,-212/729],
  [9017/3168,-355/33,46732/5247,49/176,-5103/18656],
  [35/384,0,500/1113,125/192,-2187/6784,11/84]];
const B5 = [35/384,0,500/1113,125/192,-2187/6784,11/84,0];
const B4 = [5179/57600,0,7571/16695,393/640,-92097/339200,187/2100,1/40];

function integrateAdaptive(f, state0, t0, tf, mu, tol = { rtol: 1e-11, atol: 1e-12 }) {
  let state = state0.slice(), t = t0, dt = (tf - t0) / 1000, steps = 0;
  while (t < tf) {
    if (t + dt > tf) dt = tf - t;
    const k = [];
    for (let s = 0; s < 7; s++) {
      const ys = state.slice();
      for (let j = 0; j < s; j++) if (A[s][j]) for (let m = 0; m < 6; m++) ys[m] += dt*A[s][j]*k[j][m];
      k.push(f(ys, mu));
    }
    const y5 = state.map((s, i) => s + dt * B5.reduce((sum, b, j) => sum + b*k[j][i], 0));
    const y4 = state.map((s, i) => s + dt * B4.reduce((sum, b, j) => sum + b*k[j][i], 0));
    let err = 0;
    for (let i = 0; i < 6; i++) {
      const sc = tol.atol + tol.rtol * Math.max(Math.abs(state[i]), Math.abs(y5[i]));
      err += ((y5[i] - y4[i]) / sc) ** 2;
    }
    err = Math.sqrt(err / 6);
    if (err <= 1) { t += dt; state = y5; steps++; dt *= Math.min(5, Math.max(0.2, 0.9*err**-0.2)); }
    else { dt *= Math.max(0.1, 0.9*err**-0.25); }
  }
  return { state, steps };
}

const mu = 0.0121505856;
const state0 = [1.0220215127, 0, -0.1820967615, 0, -0.1032563411, 0];
const C0 = jacobiConstant(state0, mu);
const { state: finalState, steps } = integrateAdaptive(CR3B_ode, state0, 0, 1.51111, mu);
const Cf = jacobiConstant(finalState, mu);
console.log({ steps, finalState, C0, Cf, relativeChange: Math.abs((Cf - C0) / C0) });
// steps: 465, relativeChange: ~4.1e-12

Example 3: Relative Motion (Safety Ellipse)

Problem Statement

A chief satellite is in a circular orbit ($a = 7000$ km, $e = 0$, all angles zero). A deputy satellite shares the same semi-major axis but has $\Delta e = 0.001$ and $\Delta M = 0.05°$. Using the differential-orbital-element method from the Relative Motion page, find the deputy's position relative to the chief in the LVLH frame at $t=0$ and at a quarter of the chief's orbital period, and confirm the relative motion stays bounded.

Solution

First, convert both satellites' orbital elements to ECI state vectors. The chief, being circular with all angles zero, comes out simply as $\vec{r}_{c0} = [7000, 0, 0]$ km, $\vec{v}_{c0} = [0, 7.546053, 0]$ km/s. The deputy, with its small $\Delta e$ and $\Delta M$ offsets, comes out to $\vec{r}_{d0} = [6992.9973, 6.1148, 0]$ km, $\vec{v}_{d0} = [-0.006598, 7.553600, 0]$ km/s - close to the chief, as expected for such small element differences.

The LVLH frame is built from the chief's own state: the radial unit vector $\hat x = \vec{r}_c/|\vec{r}_c|$, the cross-track unit vector $\hat z = (\vec{r}_c\times\vec{v}_c)/|\vec{r}_c\times\vec{v}_c|$, and the in-track unit vector completing the right-handed set, $\hat y = \hat z \times \hat x$. Projecting the deputy's position relative to the chief, $\vec{r}_d - \vec{r}_c$, onto these axes gives the relative position at $t=0$:

$$ \vec{r}_{\text{lvlh}}(0) = [-7.0027,\ 6.1148,\ 0.0000]\ \text{km} $$

Both satellites are then propagated forward using the exact two-body method from Example 1 (this is exactly why the DOE method is built on the two-body propagator rather than HCW - both objects are moved with zero truncation error, so any relative-motion error comes purely from the physics, not the numerics). The chief's period is $T = 5828.52$ s, so a quarter-period is $t = 1457.13$ s. Re-transforming into the (now-rotated) LVLH frame at that time gives:

$$ \vec{r}_{\text{lvlh}}(T/4) = [-0.0158,\ 20.1086,\ 0.0000]\ \text{km}, \qquad \text{range} = 20.1086\ \text{km} $$

Sweeping this same calculation across a full chief period shows the range oscillating but never exceeding about $20.11$ km before returning - confirming this is a bounded "safety ellipse" relative orbit rather than one that drifts away, which makes sense since $\Delta a = 0$ means both satellites share the same period.

Code

// Converts classical orbital elements to an ECI state vector - see the
// Orbital Elements section of the Two-Body page for the underlying equations.
function oeToStateVector(a, e, i, RAAN, w, M, mu) {
  const d2r = d => d * Math.PI / 180;
  i = d2r(i); RAAN = d2r(RAAN); w = d2r(w); M = d2r(M);
  let E = M;
  for (let k = 0; k < 30; k++) E += (M - (E - e * Math.sin(E))) / (1 - e * Math.cos(E));
  const nu = 2 * Math.atan2(Math.sqrt(1+e) * Math.sin(E/2), Math.sqrt(1-e) * Math.cos(E/2));
  const p = a * (1 - e*e), r = p / (1 + e * Math.cos(nu));
  const r_pf = [r * Math.cos(nu), r * Math.sin(nu), 0];
  const v_pf = [-Math.sqrt(mu/p) * Math.sin(nu), Math.sqrt(mu/p) * (e + Math.cos(nu)), 0];
  const cosO = Math.cos(RAAN), sinO = Math.sin(RAAN), cosi = Math.cos(i), sini = Math.sin(i),
        cosw = Math.cos(w), sinw = Math.sin(w);
  const R = [
    [cosO*cosw - sinO*sinw*cosi, -cosO*sinw - sinO*cosw*cosi, sinO*sini],
    [sinO*cosw + cosO*sinw*cosi, -sinO*sinw + cosO*cosw*cosi, -cosO*sini],
    [sinw*sini, cosw*sini, cosi],
  ];
  const rotate = v => R.map(row => row[0]*v[0] + row[1]*v[1] + row[2]*v[2]);
  return [rotate(r_pf), rotate(v_pf)];
}

// keplerStep: same exact two-body propagator as in Example 1's code above.

function eciToLvlh(rc, vc, rd, vd) {
  const norm = v => Math.hypot(...v);
  const sub = (a, b) => a.map((x, i) => x - b[i]);
  const cross = (a, b) => [a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0]];
  const xh = rc.map(x => x / norm(rc));
  const hVec = cross(rc, vc);
  const zh = hVec.map(x => x / norm(hVec));
  const yh = cross(zh, xh);
  const project = v => [xh, yh, zh].map(axis => axis[0]*v[0] + axis[1]*v[1] + axis[2]*v[2]);
  return { r_lvlh: project(sub(rd, rc)), v_lvlh: project(sub(vd, vc)) };
}

const mu = 398600.4418;
const [rc0, vc0] = oeToStateVector(7000, 0, 0, 0, 0, 0, mu);
const [rd0, vd0] = oeToStateVector(7000, 0.001, 0, 0, 0, 0.05, mu);

console.log("t=0:", eciToLvlh(rc0, vc0, rd0, vd0).r_lvlh);

const T = 2 * Math.PI * Math.sqrt(7000 ** 3 / mu);
const { r: rcQ, v: vcQ } = keplerStep(rc0, vc0, T / 4, mu);
const { r: rdQ, v: vdQ } = keplerStep(rd0, vd0, T / 4, mu);
console.log("t=T/4:", eciToLvlh(rcQ, vcQ, rdQ, vdQ).r_lvlh);
// t=0:   [-7.0027, 6.1148, 0.0000]
// t=T/4: [-0.0158, 20.1086, 0.0000]
